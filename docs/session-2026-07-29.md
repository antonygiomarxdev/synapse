## What We Built

### 1. GGUF Parser (`synapse-core/src/native_moe/gguf.rs`, 460 lines)
- Parses GGUF v3 binary format: header, metadata KV pairs, tensor index
- 42 KV pairs, 322 tensors verified against Granite MoE 3B
- Lazy tensor loading with mmap-friendly offset indexing
- F32 direct read, F16 conversion, quantized format routing

### 2. Dequantization (`synapse-core/src/native_moe/quant.rs`, 194 lines)
- Q8_0: 32-element blocks, 34 bytes (scale f16 + 32 × i8 quants) ✅
- Q6_K: 256-element superblocks, 210 bytes ✅
- Q4_K: 256-element superblocks, 144 bytes — **PARTIAL (see Known Issues)**

### 3. Model Loading (`synapse-core/src/native_moe/model.rs`, 225 lines)
- `MoeConfig`, `MoeLayer`, `MoeModel` structs with lazy weight loading
- `WeightProvider` trait for extensible weight injection (future remote workers)
- `Option<Tensor>` for all heavy weights, `gate_inp` always F32
- Architecture: shared layers (attention, norms) + gate_inp + expert FFN per layer

### 4. Forward Pass (`synapse-core/src/native_moe/forward.rs`, 177 lines)
- Embedding lookup → per-layer RMS norm → gate_inp routing
- Implements `route_experts()`: hidden @ gate_inp^T → top-k indices
- Placeholder attention and expert FFN for V0
- Output: per-layer routing decisions with expert IDs and scores

### 5. InferencePort Implementation (`synapse-core/src/native_moe/runtime.rs`, 150 lines)
- `NativeMoeRuntime` implements the `InferencePort` trait
- `load()` → parses GGUF, loads routing-critical tensors
- `generate()` → runs forward pass, returns routing info as tokens
- Plugs into existing `SwarmCoordinator` and consensus infrastructure

### 6. Coordinator-Worker E2E Spike (`scripts/spike_coordinator_e2e.py`, 123 lines)
- Coordinator dispatches same prompt to 2 workers via subprocess pipes
- Worker A: expert shard 0-19 (1.06 GB), Worker B: expert shard 20-39 (1.06 GB)
- Shards created by `scripts/split_gguf.py` (expert slicing at GGUF byte level)
- Result: **3/3 prompts diverge between workers** — expert subsets matter

### 7. Per-Token Routing Spike (`scripts/spike_per_token_routing.py`, 94 lines)

## Known Issues

### Q4_K Dequantization (HIGH PRIORITY)
**Status:** Blocked — returns zeros (placeholder) for V0 validation

**Root cause:** Some Q4_K superblocks have extreme f16 values for `d` and `dmin`
(e.g., `dmin=30096`). The formula `d * sc * nibble - dmin * m` produces NaN/Inf
when these scalars are large and the subtraction underflows/overflows.

**Attempted fixes:**
1. Clamping `d` and `dmin` to finite range — didn't help, NaNs persist
2. Integer arithmetic (`i32` instead of `f32`) with division by 256 — wrong values
3. `get_scale_min_k4` bit unpacking fix — correct implementation but edge cases remain

**Impact:** All attention, expert gate/up/down tensors (Q4_K format) use zeros.
`gate_inp` (F32) and `token_embd` (Q8_0) work correctly.
The routing validation is unaffected — F32 + Q8_0 are sufficient for the thesis.

**Recommended fix:** Study ggml's exact `dequantize_row_q4_K` for the NaN-producing
blocks. Likely the `d` value interpretation differs for certain block patterns.
Alternative: use `ggml-sys` FFI to call ggml's native dequant functions.

### Q6_K Scale (LOW)
Works correctly for the tested tensors but hasn't been stress-tested on all
32 layers. Same `d` scalar interpretation applies.

## Decisions Made

1. **No llama.cpp fork/PR** — Built own runtime to avoid maintenance burden and
   contributor approval delays. GGUF parser + dequant = full control.

2. **Rust over Python for runtime** — Performance, type safety, integration with
   existing synapse-core traits. Python for spikes only.

3. **Q4_K placeholder for V0** — Unblocks validation while fixing the NaN issue.
   Q8_0 + F32 + Q6_K cover all routing-critical tensors.

4. **`Option<Tensor>` for extensibility** — Forward loop works with or without
   loaded weights. Future remote workers inject via `WeightProvider` trait.

5. **No CUDA dependency** — CPU-only F32 arithmetic for V0. Can add GPU
   acceleration later without changing the interface.

## Next Steps for Next Developer

1. **Fix Q4_K dequant NaN** — Highest priority. Blocks attention and expert FFN
   from working with real weights. Study ggml's `dequantize_row_q4_K` for
   the edge case with extreme `dmin` values.

2. **Complete forward loop** — With Q4_K fixed, implement `attention()` and
   `expert_ffn()` in `forward.rs`. These are ~200 lines each, well-documented
   in the spike code at `spike_per_token_routing.py`.

3. **Consistency validation** — Once forward loop works: same prompt → our
   output vs llama.cpp output → must match exactly. This is the final proof.

4. **Tokenization** — Parse `tokenizer.ggml.tokens` array from GGUF metadata
   to map text ↔ token IDs. Currently hardcoded.

5. **Multi-layer** — Extend from 1-layer forward pass to full 32 layers.
   Memory management: load/dequant/release per layer to avoid OOM.
